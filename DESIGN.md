## Rules that are not negotiable

1. **`chrome.*` is invariant and cannot invert.** `color.chrome.surface.*` and
   `color.chrome.text.*` are always dark. Use them only on a surface that never
   flips — a terminal, a log panel, a code frame. Anything on a surface that
   flips uses the theme-aware `color.text.*` / `color.surface.*`. The two share
   their dark values and diverge only in light, so the wrong pick looks correct
   until someone opens light mode.
2. **A light surface on a dark page needs the `light` class on its own root.**
   Without it the mode-aware tokens resolve to their dark values against a light
   fill. That has shipped text at 1.08:1. Check the module's `polarity` first —
   `applies-light` means the module already does this for you.
3. **Content is props.** No section hardcodes copy.

Theming is class-based and the package ships base mode `dark`. Contrast floors: body text 4.5:1, large text 3:1 (WCAG 2.2).

## Surface roles

| role | tokens | behaviour | use for |
| --- | --- | --- | --- |
| `chrome` | `color.chrome.surface.*, color.chrome.text.*` | invariant, always dark | Anything that should stay dark on a light page the way a terminal or a code block does. Dashboard data tables, log panels, terminal frames. |
| `themed` | `color.surface.*, color.text.*` | mode-aware, inverts to a zinc ladder in light | page surfaces that should follow the theme. |

These two share their dark values and diverge only in light, so picking the wrong one looks correct until someone opens light mode. Collapsing them back into one set breaks a consumer in either direction, which is why `__tests__/roles.test.ts` fails the build if anyone tries.

## Known gaps

**Unproven modules.** Nothing in this repository has ever rendered this module, so its claims have no baseline behind them: `ui/sonner`.

**light_mode_brand_palette.** The brand palette was drawn against dark surfaces. The figures this entry used to quote — peach 1.53:1, matcha 1.16:1, amber 1.83:1, error-red 3.31:1 — are the UNFIXED values and are no longer what renders. 0.4.0 added light-mode variants for matcha, amber and error-red, and 0.5.1 added on-tint variants for their labels. The stale figures did real damage: a section written from this table in 0.5.0 documented a contrast risk with numbers that were two releases out of date, which sent someone looking for the wrong problem. STILL OPEN, but narrower than it reads: every one of the four now has a light variant, color.brand.peach included (#89684a, 4.61:1 on surface.1 light), and `__tests__/roles.test.ts` asserts all four clear 4.5:1. What is unfixed is that each light value is DERIVED — the least-darkened hue-preserving value that cleared the floor — so the gap is aesthetic, not accessible. KNOWN_GAPS in scripts/check-token-contrast.ts is the live list and holds only the two shadcn destructive pairs; this entry is prose and goes stale, so trust that file over this one.

**sidebar_primary_is_shadcn_blue.** --sidebar-primary was oklch(0.488 0.243 264.376), shadcn's default blue. It is now mode-aware: brand peach in dark, oklch(0.205 0 0) in light. The token's own $description records the change. Kept here as a closed entry because this list was read as open work while the value had already moved.

**Not covered by any page template.** An uncovered surface is written down, never dropped — the same precedent as an empty `seen` list.

- `(landing)/alternatives/*` — The largest page archetype on the site, and not one of its twenty routes imports anything from this package. They compose three route-local components instead — ComparisonLayout (12 routes), CategoryLayout (4) and ArchitectureComparisonTable (14).
- Matters because: ArchitectureComparisonTable is 45 lines drawing a real table of `Dimension | Skene | <competitor>`, which is sections/comparison-table's stated job almost word for word: "one row per claim, one column per approach, with your column picked out". Two implementations of one object, the shipped one carrying the horizontal-scroll and focus handling that the local one does not.
- What that means here: Read the comparison-page archetype in that light. It is derived from the two comparison routes that DID use this package, so its shape is sound, but it speaks for two routes out of twenty-two. The other twenty are not evidence against the recipe — they are evidence nobody reached for it. That is the twenty-first duplicate cluster, in a package whose whole premise is the twenty already documented, and it is a finding about the site rather than a defect in this contract.

- **everything outside the marketing site** — The corpus is one marketing site at one commit. The dashboard and docs surfaces compose these modules too; none of that is in evidence here, so none of it is claimed. machine/layouts.yaml is the file that speaks to those surfaces.

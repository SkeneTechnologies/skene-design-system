## Watch for

One route, so `load_bearing` is empty and the list above is `observed`. Do NOT read it as a checklist: seventeen bands on one page is what a home page did once, not what a page needs. Its value is that five of these modules appear nowhere else in the corpus — patterns/dither, sections/evaluator-list, sections/feature-row, sections/final-cta, sections/question-grid — so this is the only recorded evidence of how any of them is composed. Two of the five matter beyond this route: `sections/feature-row` is the marketing card `render_marketing_cards_as_feature_row` in `machine/rules.yaml` mandates, and `sections/final-cta` is the closing band. If you are building any page and have neither, that is the omission to check first. The route also composes them by hand rather than through the consumer's own page template, which is a fact about that consumer and not about this package — but it is why the file's first cut mistook it for a route that imports nothing.

## Band grammar

Source: `.webanatomy/build-page/BUILD-SPEC.md` in `skene-marketing-website`, proven on 20 pages, transcribed 2026-08-27. The template component itself (`SitePage`) is **not** shipped in this package — what follows is the contract it enforces, so a page built from these sections lands in the same grammar as the pages that ship.

**Page shape.** A page is a data declaration: a header, plus an ordered list of bands. The page supplies copy, artifacts and links and nothing else. Ground, rhythm, split geometry, which side the copy sits on, the eyebrow gap and the card recipe are all computed from a band's POSITION. The value is not that the template's answer is better than any one page's; it is that there is exactly one answer and a page cannot reach around it. Before it, one site had three mechanisms for section rhythm, four for the split at two different breakpoints, two conventions for the eyebrow gap, and fifteen hand-rolled copies of a card that already shipped.

**DOM.** fragment — the header `<div>`, then N `<section>` as direct children of `<main>` — Section addressing across the consuming repo depends on `body > main > section:nth-of-type(n)`. A container div re-paths all of them at once.

**Ground.** a page declares no ground, ever — it is a function of band index.

- Cycle by band index: 0 → `page`, 1 → `deep`, 2 → `page`, 3 → `deep`. Starts on `page`. The header above band 0 is already dark and textured, so a deep-2 first band reads as a second header.
- Cream is not a ground. Cream never grounds a section. It arrives only as a component that paints its own panel, sitting on whichever ground its position gives it.
- An override exists, for letting a page's ONE signature band sit on a ground its position would not give it. Watch for: A page that overrides every band has re-invented per-page grounds, which is the exact failure the alternation was written to end.

**Mirroring.** even mirrorable band copy-left, odd copy-right, from the top of the page. When it was authored per band, one site had eleven copy-left and three copy-right with no pattern, because each author chose separately. A band with no second track cannot mirror. Fifteen artifact bands run splitAt: never because their artifact needs 812-998px against the 640-700 a half track offers. Counting those anyway lets a full-width band consume a parity slot and produces two copy-left cards in a row with a wide one between them, which reads as a mistake rather than a rhythm.

**Rhythm.** default `py-[96px] md:py-[128px]`, tight `py-[64px] md:py-[80px]` (a dense band — a table, a terminal — that earns less air), tall `py-[128px] md:py-[176px]` (once per page: the page's signature band). Written as literal px on purpose: The package sets --spacing: 0.2rem, so py-24 is 76.8px, not 96. The literal IS the token value and is not a tidying candidate.

## Rules that are not negotiable

1. **`chrome.*` is invariant and cannot invert.** `color.chrome.surface.*` and
   `color.chrome.text.*` are always dark. Use them only on a surface that never
   flips — a terminal, a log panel, a code frame. Anything on a surface that
   flips uses the theme-aware `color.text.*` / `color.surface.*`. The two share
   their dark values and diverge only in light, so the wrong pick looks correct
   until someone opens light mode.
2. **A light surface on a dark page needs the `light` class on its own root.**
   Without it the mode-aware tokens resolve to their dark values against a light
   fill. That has shipped text at 1.08:1. Check the module's `polarity` first —
   `applies-light` means the module already does this for you.
3. **Content is props.** No section hardcodes copy.

Theming is class-based and the package ships base mode `dark`. Contrast floors: body text 4.5:1, large text 3:1 (WCAG 2.2).

## Use for

A whole dark band of a page: a copy column (corner marker, ringed icon, title, italic lede, proof list, pinned actions) beside a visual panel, mirrored per row by `reverse`. The shape is an argument, not a layout — `title` + `lede` are the promise and `children` (usually a `CheckList`) is the proof, which is why the lede is its own slot rather than the first paragraph of the body. Ships with `FeatureStack` (the `grid gap-6` rhythm wrapper) and `FeatureIcon` (a ringed accent glyph in peach/violet/blue) so a three-row feature section is three prop sets rather than a re-derived grid.

## Watch for

| note | via |
| --- | --- |
| Dark-surface only. The root is `bg-chrome-surface-1` and the title uses `text-chrome-text-primary` — invariant `chrome.*` tokens that by definition cannot follow a `light` ancestor (docs/sections.md rule 1). Adding `light` to `className` will not invert it. | `prop FeatureRow.title` |
| `min-h-[600px]` applies at every breakpoint, and `actions` is pinned with `mt-auto` against that height. A short row will be mostly whitespace; `cn` is twMerge so `className="min-h-0"` wins, but then the actions pinning stops meaning anything. | `prop FeatureRow.actions` |
| `reverse` only takes effect at `md:` (it sets `md:col-start-*`) — below md the copy column is always first. And it must be set explicitly per row: deriving it from an index breaks the moment a row is inserted or reordered, and these rows are content. | `prop FeatureRow.reverse` |
| There is an always-on sheen over the visual cell — an `aria-hidden pointer-events-none` span with a hardcoded white 135° gradient. It is not a prop and cannot be switched off; harmless over a mock, visible over a photograph. | `prop FeatureRow.visual` |

## Constraints

From `machine/components.yaml` (`sections.FeatureRow`).

| prop | allowed |
| --- | --- |
| `reverse` | boolean — mirrors the layout |
| `lede` | the italic promise line under the title |
| `actions` | buttons, pinned to the bottom of the copy column |
| `accent` | `peach`, `violet`, `blue` |

- Set `reverse` explicitly per row. Deriving it from index breaks the moment a row is inserted or reordered, and these rows are content.
- The line under the title is `lede` and the buttons are `actions`, the same names LightSectionCard and FinalCta use. These were `subtitle` and `action` until 2026-08-12; one concept under two names is drift that gets copied, so do not reintroduce the old names.
- accent.violet / accent.blue exist for FeatureIcon specifically; the nearest neon.* is dE 24+ and far too saturated at a 44px ring.
- `n` is a CORNER MARKER — absolutely positioned at right-6 / top-[22px], 11px, muted-warm — and it is aria-hidden unconditionally. It is not the baseline ordinal a marketing wireframe draws beside a heading; that mark is a flex sibling of the head at 12px. If your page draws the second one, `n` is the wrong element and no prop turns it into the right one.
- There is no `copyOnly` prop. The mode is derived at render as `!visual && !texture && !textureSrc`, and with it the 600px floor, `splitAt` and `reverse` all go inert. So it is invisible at the call site, and adding a `texture` later silently restores the floor.

## What binds this module

- **Polarity `inherits`.** It puts no theme class on its own root, so it takes the page. Place it on a light fill and the `light` class is yours to add, or its mode-aware tokens resolve to their DARK values against that fill — measured at 1.07:1 on rendered pixels.
- **`chrome.*` is invariant.** This module is in the fixed-dark world, so the distinction bites here: `chrome.*` never inverts and belongs only on a surface that never flips. Anything on a surface that follows the theme uses `text.*` / `surface.*`. The two share their dark values, so the wrong pick looks correct until someone opens light mode.
- **Content is props.** This section hardcodes no copy; the page supplies it.

These are the rules this module can break. The full set, the surface roles and
the contrast floors are in [DESIGN.md](../../DESIGN.md).

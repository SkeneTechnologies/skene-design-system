## Use for

A labelled progress track: N steps with state rings, joined by connectors the STEPPER owns and fills from the state of the step on their left, above an optional title/subtitle. It was built for a long job running inside a light `ProductWindow`, and two decisions carry that job — connectors are derived rather than drawn per-step, so N dots read as one track filling left to right; and emphasis runs backwards from instinct, with the ACTIVE step taking the label weight and a peach halo while done steps recede to matcha, because a running job's question is "what is it doing now", not "what has it finished".

## Watch for

| note | via |
| --- | --- |
| `aria-current="step"` on the active step is the ONLY state exposed to assistive tech; the rings and glyphs are `aria-hidden` on purpose. Nothing is enforced, so two `active` steps emit two `aria-current="step"`, and `done` vs `pending` is invisible to a screen reader — if completion must be announced, it has to be in the `label`. | `type PipelineStepItem.label` |
| The connector reads only the LEFT step's state, so an out-of-order array renders literally: a `done` after a `pending` draws a filled matcha rule leading into a hollow ring. | `type PipelineStepItem.state` |
| The geometry is hand-computed and interlocking: a fixed 38px ring, and connector offsets of `ml-[18px]` (stacked) and `sm:mt-[18px]` (row) that are exactly its centre. Change the ring size and the track stops aligning with the rings. Steps also cap at `sm:max-w-[160px]`. | `prop PipelineStepper.steps` |
| The breakpoint is `sm`, not `md` (the header notes three labelled steps need roughly 390px), and the root padding is a fixed `p-[22px]` sized for a ProductWindow body — both are worth re-checking if you drop this into a narrower or differently-padded container. | `prop PipelineStepper.steps` |

## What binds this module

- **Polarity `inherits`.** It puts no theme class on its own root, so it takes the page. Place it on a light fill and the `light` class is yours to add, or its mode-aware tokens resolve to their DARK values against that fill — measured at 1.07:1 on rendered pixels.
- **`chrome.*` is invariant.** This module is in the fixed-dark world, so the distinction bites here: `chrome.*` never inverts and belongs only on a surface that never flips. Anything on a surface that follows the theme uses `text.*` / `surface.*`. The two share their dark values, so the wrong pick looks correct until someone opens light mode.
- **Content is props.** This section hardcodes no copy; the page supplies it.

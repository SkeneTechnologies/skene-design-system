## Constraints

From `machine/components.yaml` (`sections.KeyValueTable`).

| prop | allowed |
| --- | --- |
| `density` | `reference`, `data` |
| `headerless` | boolean — renders a semantic `<dl>` instead of a `<table>` |
| `TagChip.variant` | `outline`, `solid` |

- `rows` is DATA here and `children` in DataTable, and the split is the whole point of having two components. Formatting that is a property of the COLUMN belongs on the column; it is what stops the tenth subprocessor row being the one that forgot `mono`. Anything genuinely per-cell still goes in the cell as a node — that is what TagChip and MaskedValue are for.
- `density` exists because the four call sites had already drifted into two: the prototype's .ptab and .dtab differ by 4px of vertical padding, a vertical-align, a hover fill and tabular-nums. That is one design at two densities. Do not add a third by overriding padding from a call site.
- `reference` density defaults column 0 to mono and nowrap, and that is sourced, not stylistic: the page notes enumerate where mono may appear and name the permission column, because that column holds things a reader matches against their own config. It is a default, not a rule — `mono: false` on the column turns it off where the first column is prose.
- `headerless` is a real `<dl>`, not visually-hidden `<th>`s, and it drops the header row for the readout whose headings would only repeat what every row says. Keep authoring the column `header`s anyway: they document the columns and every other column flag still applies.
- Nothing here sets a width or a min-w. The table scrolls inside ui/table's overflow-auto container, cells wrap, and only column 0 refuses to. Adding a width at a call site is what turns a table that scrolls into a page that scrolls.

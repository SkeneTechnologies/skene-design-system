## Use for

A responsive card band whose argument is carried by tone rather than by copy: N cards stating what the current situation costs, then one stating what it becomes. `ValueCard` takes a mono `label`, a `title` line and an optional body, and the `tone` union (`'cost' | 'gain'`) is the only thing that moves — `cost` borrows `semantic.errorRed` for the label and a neutral 14% hairline, `gain` takes `brand.peach` with a 34% border and a left-to-right directional wash so the last card reads as an arrival rather than one more tile. It exists so a band can make a turn; a row of identically-weighted cards degrades into a feature list and says nothing.

| `QuestionGrid` | A row of equal-weight peers (a feature list, a set of capabilities). The whole point of the component is the tonal turn; used flat it is a worse plain card grid than `QuestionGrid` or `FeatureRow`. |
| `Finding` | Signalling a measured state. The `good \| warn \| danger` vocabulary bound to `semantic.matcha / warningAmber / errorRed` means an observed fact — that is `Finding` (or `ui/badge` on a product surface). `ValueCard`'s `cost` borrows `errorRed` for a marketing claim, and using it for real status teaches the reader that red means two different things. |

## Watch for

| note | via |
| --- | --- |
| `tone` defaults to `'cost'`. That is deliberate (costs are the majority of the band) but it means a forgotten `tone` renders a red label, not a neutral one. | `default tone='cost'` |
| The accent lands via inline `style={{ color: accent }}` on the label and inline `borderColor`/`backgroundImage` on the `<article>`. A `text-*` or `border-*` utility passed through `className` will not win against those; to retint, add a tone member to `TONE_ACCENT` rather than fighting it from the call site. | `prop ValueCard.label` |
| `ValueCards` deliberately carries no `light`/`dark` class — everything is derived from the mode-aware `text.primary` and `brand.peach`, so it inherits polarity. Per rule 2 in docs/sections.md, a caller putting this band on a cream panel inside a dark page still owes that panel its own `light` class, or the 1.8% wash and the hairline resolve to their dark values against cream. | `export ValueCards` |
| The `gain` wash is directional — `linear-gradient(90deg, …, transparent 62%)` — and knows nothing about position. It always enters from the left edge, which reads as arrival only when the gain card is last in the row; below `md` the grid stacks to one column and the horizontal gradient stops doing any sequencing work at all. | `inline style` |
| `ValueCard` renders an `<article>` whose title is a `<strong>`, not a heading. The cards therefore never appear in the document outline. `title` is `React.ReactNode`, so pass your own `<h3>` if these need to be navigable. | `export ValueCard` |
